# Base model baseline, 2026-09-20

The unmodified Qwen3.5-0.8B reached 35.25% accuracy on public validation slices, compared with 84.75% for Jev on the same questions. This run also verified HTTP calls to the local service through the official Python SDK.

Convolution and linear attention used the PyTorch reference implementations on Windows.

## Judgment results

| Data | Questions | Base model | Jev 1.13.0 |

| Custom English and Chinese development examples | 24 | 22/24 | 24/24 |
| XNLI English | 100 | 39% | 93% |
| XNLI Chinese | 100 | 41% | 74% |
| MASSIVE English, 60 classes | 100 | 34% | 89% |
| MASSIVE Chinese, 60 classes | 100 | 27% | 83% |
| Public slices combined | 400 | 35.25% | 84.75% |

The development examples were used to adjust prompts. The public slices diagnosed candidate scoring and later became a regression set. Sources and metric definitions are documented in [Evaluation](../evaluation.md).

On the public slices, NLL was 2.5224 for the base model and 1.2230 for Jev. Brier scores were 0.7770 and 0.2239, respectively. NLL clipped zero probabilities at `1e-12`.

## Performance

The same short English refund text with three candidates was run 20 times after warmup. Timing covered the local engine call.

| Questions per request | Input tokens | p50 | p95 | Peak PyTorch allocated memory |
|---|---:|---:|---:|---:|
| 1 | 109 | 51.94 ms | 57.68 ms | 1.64 GiB |
| 4 | 436 | 59.21 ms | 60.85 ms | 1.70 GiB |

Local batch inference on 400 questions took 31.26 seconds, approximately 12.80 questions per second, with peak allocated memory of 1.94 GiB. Jev took 39.16 seconds for the same requests, including network time and concurrent client scheduling.

## API and label scoring

All 44 automated checks passed in this run. The GPU service was tested through the official SDK for all three response types, Chinese input, model listing, and authentication.

An HTTP request with 255 options returned a complete distribution summing to 1, but selected the wrong option: `item-054` instead of the expected `item-254`. It took approximately 0.56 seconds.

The initial JSON wrapper and uniform letter labels scored 17/24 on development examples. Direct text prompts and Yes/No labels for Noul increased this to 22/24.

For large candidate sets, mixing single-letter and multi-letter labels introduced position bias. Fixed-width two-letter labels showed no clear improvement. The final implementation for this run used full-sequence scoring of fixed-width numeric labels and reused the input cache.

Per-candidate binary matching reached 52.5% on 40 English MASSIVE diagnostic questions and took approximately 38.6 seconds. Full-sequence numeric scoring remained the default, followed by the [first LoRA experiment](lora-pilot-2026-09-20.md).
