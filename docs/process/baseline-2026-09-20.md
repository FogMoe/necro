未微调的 Qwen3.5-0.8B 在公开验证切片上准确率为 35.25%，同题 Jev 为 84.75%。本次同时验证了本地服务与官方 Python SDK 的 HTTP 调用。

## 性能

对同一条英文退款短文本、三个候选项预热后运行 20 次，计时范围为本地引擎调用。

| 每请求问题数 | 输入 tokens | p50 | p95 | PyTorch 峰值已分配显存 |
|---|---:|---:|---:|---:|
| 1 | 109 | 51.94 ms | 57.68 ms | 1.64 GiB |
| 4 | 436 | 59.21 ms | 60.85 ms | 1.70 GiB |

400 题本地批量推理用时 31.26 秒，约 12.80 题/秒，峰值已分配显存 1.94 GiB。Jev 的同批请求用时 39.16 秒，包含网络和客户端并发调度。

## 接口与标签评分

本轮 44 项自动检查通过。实际 GPU 服务经官方 SDK 验证三种响应、中文输入、模型列表和鉴权。

255 选项的 HTTP 请求返回完整分布，概率总和为 1，但选择错误。预期 `item-254`，实际为 `item-054`，耗时约 0.56 秒。

初始 JSON 包装与统一字母标签在开发样例上为 17/24。改为直接文本提示、Noul 使用 Yes/No 后为 22/24。

大候选集合中，混用单字母与多字母出现位置偏差，等长双字母也没有明显改善。本轮最终采用等长数字的完整序列评分，并复用输入缓存。

逐候选二元匹配在 40 道英文 MASSIVE 诊断题上为 52.5%，耗时约 38.6 秒。本轮保留数字完整序列评分作为默认实现，随后开展 [首轮 LoRA 实验](lora-pilot-2026-09-20.md)。
